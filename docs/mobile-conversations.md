# Mobile conversations and setup

The iOS conversation browser groups saved chats under Agent and Supervisor. Each
group has New chat. The two original shared chats are retained after upgrading.
Named chats have independent drafts, histories and server sessions. The catalog
and message previews are cached for the current server pairing.

An updated server exposes `GET /conversations`, `POST /conversations` with
`{thread, sourceId?}`, and accepts `conversationId` on the existing shared history
and message routes. New IDs are generated by the server. A named conversation
never retries a send into a default chat on an older server.

Paired owner phones can read human-visible web chat history. The catalog exposes
opaque web identifiers, user/assistant text and image previews, not tool results
or authority metadata. Continue in new chat copies at most the latest 50 visible
messages into a fresh device session. It never reuses the web session ID,
computer-control lease or approval state. G2 and generic node credentials do not
gain access to web history or the catalog.

The microphone in Chat and Supervisor starts native on-device dictation only
after permission. Stop keeps the transcript in the draft. Send is a separate
action. Backgrounding, navigation, editing or sending stops recognition. If the
current language has no on-device recognizer, the app explains the limitation
and offers the system keyboard's dictation as an alternative.

On supported iPhones, first run opens a conversational guide. Choosing local
setup selects and tests Apple Intelligence automatically, then asks for an agent
name and notification preference. Without a ready on-device model, setup starts
with explicit steps. Both presentations offer server pairing, and the guide
explains where to obtain its one-time code. Guide replies cannot pair a server,
connect accounts, invoke tools or change credentials. No OpenAGI account is
required. Provider credentials belong in secure model settings.

Small-model requests include the current user message once, preserve bounded
reference-context delimiters, and advertise task creation only for task requests.
Conversation responses must report actual tool outcomes rather than repeat a
previous task confirmation.
